# Homestand Plan 4: the app (Check, Fix, Send, The Study)

Branch `hs-plan-4-app`. Local commits only. No live Qloo request until Opus says "Qloo go"; everything below is built against synthetic fixtures first.

Spec: `docs/superpowers/specs/2026-10-03-homestand-design.md` (sections 1, 3, 5-9) with the changes in the build brief: guided flow, vanilla TS + Vite, one Cloudflare Worker, "Classic night", no "Season fit", market-relative index from a 40-market reference set.

## Decisions (made without the owner, flagged for review)

1. **Protected nights.** A night is never swapped when `locked` is yes. A sponsor alone does not lock a night: a swap keeps the sponsor and the date (the product promise). Locked and "Leans away" gets a worded sponsor-compatible angle instead.
2. **Request shape** is Amendment 4 exactly: `/v2/insights`, one call per entity type, `filter.results.entities` = every bundle ID of that type, `signal.location=POINT(lon lat)`, radius 80000, `filter.release_year.min=1900` on movie calls. `take` is sent (= number of IDs) when a type has more than 20 IDs. Qloo's default `take` is not verifiable offline, so the coverage script reports returned-vs-requested counts.
3. **One call per type means 5 calls per market** for the whole library (movie, tv_show, artist, book, brand). A market's whole library score is one KV record.
4. **Bundle rule is the study's:** any missing entity makes the theme "Not scored" for that market.
5. **z uses the population SD** (same as `src/study/stats.ts`). A reference SD under 1e-6 gives no z, so "Not scored" with a stated reason.
6. **Memo numbers.** The memo cites the bundle score and z (derived), never per-entity raw affinities. `DATA_RIGHTS.md` is updated to say so. Raw per-entity numbers show only inside the app behind "Show the numbers", with Qloo attribution.
7. **No per-market affinities are ever committed.** Committed Qloo-derived data: entity IDs and per-theme reference aggregates only. Until the reference script runs, `reference-stats.json` is a clearly flagged synthetic placeholder and the UI shows a "Synthetic demo data" banner.
8. **Synthetic mode.** `[env.check]` sets `QLOO_MODE=synthetic`: the Worker answers Qloo calls from a deterministic hash function, with no network. Same code path otherwise.
9. **The Study page.** Renders `study/results.json` when present (Vite `import.meta.glob`, so the build does not break when it is absent). In production builds with no file it shows only a "Results pending" state; a synthetic fixture renders (with a loud banner) in dev and when `VITE_STUDY_FIXTURE=1` (e2e).
10. **Icons** are Phosphor raw SVGs (`@phosphor-icons/core`), no hand-drawn paths.

## Worker routes

| Route | Does | Qloo calls |
|---|---|---|
| GET `/api/health` | mode, caps remaining | 0 |
| GET `/api/geocode?q=` | Open-Meteo geocoding (rate-limited) | 0 |
| POST `/api/analyze` | resolve themes (aliases, then one batched model call for leftovers), score market (KV cache), flag | 0 cached, 5 cold |
| POST `/api/propose` | constraints + ranking in code, one batched model call for the whys (guarded) | 0 cached |
| POST `/api/recheck` | re-score one theme live, bypass cache, update cache | 1 to 3 (one per type in the bundle) |
| POST `/api/memo` | recompute facts for approved swaps, one guarded model call for the summary | 0 cached |

Protection: CORS allow-list, per-IP rate limit (KV), daily cap on live Qloo calls (400), daily model budget (templates when spent). Every response carries a `trace`.
